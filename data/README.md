# 使うデータ

推薦地点を作るために使うオープンデータです。対象地域は **神奈川県川崎市** です。

推薦するのは、行って楽しく、ぬいを連れて行きやすい場所です。公園・緑地と、文化・生涯学習の施設（美術館、図書館、市民館など）を対象にします。

## データの一覧

| データ | 提供元 | 使い道 | ライセンス |
|---|---|---|---|
| 3D都市モデル（PLATEAU）川崎市 2022年度の関連データセット | 国土交通省 | 公園・緑地（名前、種類、面積、緯度経度） | PLATEAU サイトポリシー（商用利用を含め無償で利用可） |
| 公共施設一覧 | 川崎市 | 文化・生涯学習の施設（名前、緯度経度） | CC BY 4.0 |
| 駅別乗降客数 | 国土交通省（国土数値情報） | 駅の位置と、1日の乗降客数 | CC BY 4.0 |

ダウンロードしたファイルは `data/raw/` に置きます（git には入れません）。

### PLATEAU 川崎市の公園情報

- ページ: https://www.geospatial.jp/ckan/dataset/plateau-14130-kawasaki-shi-2022
- ファイル: 「関連データセット（v4）」の `14130_kawasaki-shi_2022_related.zip`（237KB）。中の `14130_kawasaki-shi_city_2022_park.geojson` を使う
- 件数: 873件。すべて点（Point）で、緯度経度がある
- 使う列: `公園名`、`公園種別`、`供用済面積`（㎡）
- ほかの列: `供用開始年`、`所在地市区町村名`、`管理市区町村`、`都市計画決定`
- 公園ごとの ID はないので、ファイルの並び順で `park_0001` のように番号を付ける

`公園種別` はコードで入っています。川崎市のデータに出てくるのは次の値です。

| コード | 種類 | 件数 |
|---|---|---|
| 1 | 街区公園 | 759 |
| 2 | 近隣公園 | 31 |
| 3 | 地区公園 | 6 |
| 4 | 総合公園 | 4 |
| 5 | 運動公園 | 1 |
| 9 | 特殊公園 | 4 |
| 11 | 都市緑地 | 51 |
| 12 | 緑道 | 15 |
| 13 | 都市林 | 2 |

コードと種類の対応は、国土数値情報（都市公園）の公園種別コードと同じとみなしています。神奈川県の公園データの件数（街区公園、都市緑地、緑道などの数）とも合っています。

次の公園は推薦地点にしません。

- 面積が 1,000㎡ 未満の公園（434件）。小さな児童公園が多く、推薦の上位を埋めてしまうため
- 霊園（緑ヶ丘霊園）

残りは438件です。

### 川崎市 公共施設一覧

- ページ: https://www.city.kawasaki.jp/170/page/0000116229.html
- ファイル: `141305_public_facility.csv`（Shift_JIS、令和7年3月時点の情報）
- 件数: 1,645件。緯度経度があるのは414件（公園の1,231件には緯度経度がない）

| POIコード | 施設の種類 | 件数 | 例 |
|---|---|---|---|
| 802 | 博物館・美術館 | 4 | 藤子・F・不二雄ミュージアム、岡本太郎美術館 |
| 803 | 記念館・資料館 | 4 | 東海道かわさき宿交流館、大山街道ふるさと館 |
| 1012 | ホール | 3 | 川崎市アートセンター、ラゾーナ川崎プラザソル |
| 1016 | 音楽ホール | 2 | ミューザ川崎シンフォニーホール |
| 1305 | 市民館・会館 | 20 | 中原市民館、川崎能楽堂、川崎市平和館 |

学校、消防、区役所などは外します。また、`備考` に「移転」とある施設も外します。川崎市市民ミュージアムは「令和５年１０月に仮設施設に移転」とあり、座標の場所にはもう施設がありません。

観光施設だけをまとめた座標つきのデータは、川崎市にはありませんでした。ミュージアムや交流館のように、上の文化施設が観光スポットも兼ねています。

### 駅別乗降客数

- ページ: https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-S12-2024.html
- ファイル: `S12-25_GML.zip`（2024年度版、6.6MB）。中の `UTF-8/S12-25_NumberOfPassengers.geojson` を使う
- 地物: 駅ごとの線（LineString）。中心の点を駅の位置とする
- 使う列: `S12_001`（駅名）、`S12_002`（運営会社）、`S12_003`（路線名）、`S12_061`（2024年度の1日の乗降客数）。乗降客数は2011年度から年度ごとに4列ずつ並び、その最後の列が `S12_061`
- 同じ駅が路線ごとに複数行ある（例: 川崎）。駅名でまとめ、乗降客数は合計する
- 全国のデータなので、川崎市の周り（東京都や横浜市の駅も含む）だけを使えば足りる

## spots.json の作り方

1. 公園情報から、推薦地点にする公園を取り出す
2. 公共施設一覧から、上の `POIコード` の施設を取り出す
3. 各地点に、いちばん近い駅を結びつける
4. 次の形で書き出す

| 項目 | 公園 | 施設 |
|---|---|---|
| `id` | `park_` ＋ 並び順の4桁 | `facility_` ＋ 公共施設一覧の `ID` |
| `category` | `公園・緑地` | `文化・生涯学習` |
| `attrs.nearest_station` | いちばん近い駅の名前 | 同じ |
| `attrs.station_distance_m` | その駅までの直線距離（メートル） | 同じ |
| `attrs.station_passengers` | その駅の1日の乗降客数 | 同じ |
| `attrs.area_m2` | 面積（㎡） | `null` |
| `attrs.park_type` | 公園の種類（総合公園など） | `null` |
| `attrs.facility_type` | `null` | 施設の種類（博物館・美術館など） |

## 推薦のルール

点数は次の3つを 0〜1 にそろえ、重みを付けて足します。重みと値は `backend/app/recommend.py` の先頭にまとめてあります。

| 要素 | 重み | 考え方 |
|---|---|---|
| 現在地からの近さ | 0.45 | 近いほど高い。3km より遠い地点は推薦しない |
| 地点の大きさ | 0.35 | 公園は面積が広いほど高い（1,000㎡で 0、100万㎡で 1 になるよう対数で計算）。施設は種類で決める（下の表） |
| 駅からの近さ | 0.2 | ぬいを連れて電車で行きやすい |

施設には面積がないので、種類ごとに大きさの代わりの値を決めています。出かける先として楽しめる施設ほど高くし、市民館と図書館は低くしています。

| 施設の種類 | 値 | 同じ値の公園の広さ |
|---|---|---|
| 博物館・美術館 | 0.9 | 約50ha |
| 記念館・資料館、音楽ホール | 0.7 | 約13ha |
| ホール | 0.6 | 約6ha |
| 市民館・会館、図書館 | 0.3 | 約8,000㎡ |

点数の順に並べたあと、次の2つで選び直します。

- 50m より近い地点は同じ建物とみなし、点数の高い方だけを残す（アートガーデンかわさきと川崎図書館は同じビルにある）
- 1つのカテゴリから返すのは3件まで。公園と施設が両方出るようにする（ほかのカテゴリが足りないときは超える）

### 推薦理由

推薦理由には、その地点を選んだわけを、点数への寄与が大きい要素から順に書きます。どれもデータから分かる事実です。

| 要素 | 書くこと |
|---|---|
| 現在地からの近さ | 現在地からの直線距離。1.2km 以内なら「と近い」を付ける |
| 地点の大きさ | 公園は広さと種類。現在地から 3km 以内の公園で3番目までに広ければ、その順位も書く。施設は種類 |
| 駅からの近さ | いちばん近い駅と、そこからの徒歩の分数 |

川崎駅を現在地にした結果は次のとおりです（実データで試した結果）。

| 地点 | 点数 | 推薦理由 |
|---|---|---|
| アートガーデンかわさき | 0.92 | 現在地から約170mと近い。博物館・美術館。川崎駅から徒歩3分 |
| ミューザ川崎シンフォニーホール | 0.85 | 現在地から約200mと近い。音楽ホール。川崎駅から徒歩3分 |
| ラゾーナ川崎プラザソル | 0.80 | 現在地から約230mと近い。ホール。川崎駅から徒歩3分 |
| 富士見公園 | 0.64 | 現在地から約1.3km。広さ11.7haの総合公園で、半径3km以内の公園で一番広い。港町駅から徒歩8分 |
| さいわい緑道 | 0.59 | 現在地から約850mと近い。広さ2.2haの緑道。川崎駅から徒歩11分 |

武蔵小杉では、広さが決め手になった公園は広さから書きます（例：多摩川緑地は「広さ72.1haの運動公園で、半径3km以内の公園で一番広い。現在地から約1.3km。多摩川駅から徒歩7分」）。

徒歩の分数は、直線距離を 80m で割って切り上げます（直線距離なので目安です）。

## あとから足すデータ（中間発表のデータ）

本番前日の中間発表で配られるデータは、次の手順で推薦に足します。座標（緯度と経度、または GeoJSON の地物）を持つデータなら、コードをほとんど書かずに足せます。

1. ファイルを `data/raw/extra/` に置く（CSV か GeoJSON）
2. `data/prepare.py` の `EXTRA_SOURCES` に1行足し、`python data/prepare.py` を実行する。各地点の `attrs` に値が入る
   - `"mode": "count"`：地点から `radius_m` 以内にある地物（点、線、面）の数
   - `"mode": "nearest"`：いちばん近い地物までの距離（m）。面の中にある地点は 0
   - CSV は `lat_col` と `lng_col` で緯度と経度の列名を指定する（既定は `緯度` と `経度`）。GeoJSON は点、線、面を形のまま扱い、座標のない地物は飛ばす
3. `backend/app/recommend.py` の `EXTRA_RULES` に同じキーで、重み、点数が 1 になる値、推薦理由に足す文を書く。足した重みの分だけ全体を割り直すので、点数は 0〜1 のまま。`full` を 0 にするなど書き間違えると、API の起動時にエラーで知らせる
4. API を起動し直す

たとえば、配られたデータが催しの会場の一覧なら、次のように書きます（キーやファイル名は例です）。

```python
# data/prepare.py
EXTRA_SOURCES = [
    {"key": "events_500m", "file": "events.csv", "mode": "count", "radius_m": 500},
]

# backend/app/recommend.py
EXTRA_RULES = {
    "events_500m": {"weight": 0.2, "full": 5, "reason": "半径500m以内に催しの会場が{value}か所"},
}
```

`full` は点数が 1 になる値です。負の値にすると、値が小さいほど点数が高くなります（`nearest` の距離に使う）。座標を持たず、市区町村や駅名で結びつくデータは、`prepare.py` に読み込みの関数を足してください。

## Project LINKS のデータについて

Project LINKS の公開データは、推薦の must には使いません。調べた結果は次のとおりです。

- 観光統計は都道府県単位、鉄道とバスは事業者単位なので、市の中の地点の評価には使えない
- 空き家・空き地バンクの物件データは最寄り駅を持つが、川崎市の物件は0件だった。また、空き家の数は「行って楽しい場所」を選ぶ理由にならない
- ドローンの飛行計画は1か月分が最大1GBあり、2024年7月分には川崎市内の計画がなかった

本番前日の中間発表で配られるデータは、「あとから足すデータ」の手順で取り込みます。
